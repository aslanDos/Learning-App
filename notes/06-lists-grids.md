# 06. Lists & Grids — списки и сетки

Ветка: `lesson/06-lists-grids`. Пример: [`lib/main.dart`](../lib/main.dart).
Предыдущий урок: [Scrolling](05-scrolling.md).

## Когда нужен список, а когда сетка

| Задача | Виджет |
| --- | --- |
| Несколько заранее известных разных элементов | `ListView(children: [...])` |
| Много однотипных строк из данных | `ListView.builder` |
| Строки с разделителями между ними | `ListView.separated` |
| Каталог карточек в несколько колонок | `GridView.builder` |

ListView и GridView уже поддерживают прокрутку. Не нужно добавлять
SingleChildScrollView, чтобы они начали прокручиваться.

## Ленивое создание через builder

```dart
ListView.builder(
  itemCount: 60,
  itemExtent: 72,
  itemBuilder: (context, index) {
    return ListTile(title: Text('Элемент ${index + 1}'));
  },
)
```

- `itemCount` — число элементов данных.
- `index` начинается с нуля: для 60 элементов это индексы 0…59.
- `itemBuilder` создаёт виджет для указанного индекса.
- `itemExtent` задаёт размер строки вдоль оси прокрутки: здесь высоту 72.

Builder не обязан создавать все 60 виджетов при открытии экрана.
Он создаёт нужные сейчас ячейки, включая некоторое количество за пределами окна для кеша.
Поэтому «создаёт только то, что видно» — полезное упрощение, но не точное правило.
Не нужно заранее создавать 60 виджетов и возвращать их из готового списка:
данные могут существовать заранее, виджеты создавай в builder.

Builder может вызываться повторно. Не запускай в нём запросы к серверу,
не увеличивай счётчик просмотров и не меняй состояние экрана как побочный эффект.

`itemExtent` уместен, когда строки действительно имеют одинаковый размер.
Для текста переменной высоты, особенно с увеличенным системным шрифтом,
фиксированная высота может оказаться неподходящей.

## ListView.separated

```dart
ListView.separated(
  itemCount: 60,
  itemBuilder: (context, index) => SizedBox(
    height: 72,
    child: ListTile(title: Text('Элемент ${index + 1}')),
  ),
  separatorBuilder: (context, index) => Divider(height: 8),
)
```

`separatorBuilder` задаёт промежуток между соседними элементами.
Для 60 строк будет 59 разделителей. Перед первой и после последней строки
разделители не добавляются. Для внешних отступов используй `padding` списка.
`Divider.height` — занятая разделителем высота, а не толщина линии.

## GridView.builder

```dart
GridView.builder(
  itemCount: 60,
  gridDelegate: SliverGridDelegateWithFixedCrossAxisCount(
    crossAxisCount: 2,
    mainAxisSpacing: 8,
    crossAxisSpacing: 8,
    childAspectRatio: 1,
  ),
  itemBuilder: (context, index) => Card(
    child: Center(child: Text('№ ${index + 1}')),
  ),
)
```

Для вертикальной сетки:

- `crossAxisCount` — число колонок;
- `crossAxisSpacing` — промежуток между колонками;
- `mainAxisSpacing` — промежуток между рядами;
- `childAspectRatio` — ширина ячейки / высота ячейки;
- `mainAxisExtent`, если задан, определяет высоту вместо расчёта по пропорции.

В общем случае childAspectRatio — размер по поперечной оси, делённый на размер
по главной оси. Для горизонтальной сетки это уже высота / ширина.

При пропорции 1 ячейка квадратная. При увеличении числа колонок доступная
ширина каждой ячейки уменьшается, следовательно, уменьшается и её высота.
Размер ячейки задаёт сетка: внутренний SizedBox не может произвольно отменить эти ограничения.

Для вертикальной сетки расчёт ширины ячейки:

```text
(Ширина окна − левый padding − правый padding − промежутки между колонками)
/ число колонок
```

В примере на экране шириной 320 окно имеет ширину 288 после полей страницы.
С padding сетки по 8 и двумя промежутками по 8 ширина каждой из 3 ячеек:
`(288 − 16 − 16) / 3 ≈ 85.3`.
Внутренняя карточка дополнительно имеет собственный margin.

Есть также `SliverGridDelegateWithMaxCrossAxisExtent`: он выбирает количество
колонок с учётом доступной ширины и заданного максимального поперечного размера ячейки.
Подробнее адаптивность разберём в Responsive UI.

## Состояние ячеек и ключи

Ячейка, ушедшая далеко за пределы viewport и кеша, может быть удалена из дерева.
Не храни единственную копию важного пользовательского выбора только в её локальном State.

В приложении выбранные индексы находятся в `Set<int>` у состояния экрана:

```dart
final Set<int> selected = {};

// В обработчике нажатия внутри setState:
if (!selected.add(index)) {
  selected.remove(index);
}
```

Builder читает этот Set и восстанавливает отображение выбора при создании ячейки.
В настоящем каталоге лучше хранить идентификаторы данных, например `product.id`.
Индекс подходит здесь, потому что данные не добавляются, не удаляются и не переставляются.

Key помогает сопоставлять виджеты, но не является постоянным хранилищем состояния.
Если порядок данных меняется, используй стабильный ключ по ID и при необходимости
`findChildIndexCallback`, чтобы связать ключ с новым индексом в builder-списке.
Key сам по себе не возвращает State, который уже был уничтожен.

## Конечное окно и shrinkWrap

В примере список или сетка находятся в SizedBox высотой 300 и шириной до 480.
У внутренней прокрутки свой ScrollController и `primary: false`.
Контроллер освобождается в dispose, смена раскладки создаёт новый и сбрасывает смещение.

На обычном экране с заголовком часто подходит структура:

```dart
Column(
  children: [
    Text('Каталог'),
    Expanded(
      child: ListView.builder(
        itemCount: 60,
        itemBuilder: (context, index) => Text('Элемент $index'),
      ),
    ),
  ],
)
```

Внешняя Column должна получить конечную высоту, например в body у Scaffold.

`shrinkWrap: true` подбирает размер области прокрутки по содержимому.
Это дополнительная работа, особенно при прокрутке и изменениях layout.
Большой список внутри SingleChildScrollView с shrinkWrap может потерять преимущество
ленивого построения. Обычно лучше дать длинному списку собственное ограниченное окно
или собрать единый экран через slivers — отдельная тема курса.

## Практика

1. Открой список. Почему элемент 60 ещё не создан как виджет?
2. Выбери элемент 1, нажми «В конец», затем «В начало». Почему выбор сохранился?
3. Переключись на «Разделители». Чем их размер отличается от padding?
4. Выбери «Сетка», сравни 2 и 3 колонки. Почему меняются обе стороны ячейки?
5. В коде установи `childAspectRatio: 2`. Предскажи высоту вертикальной ячейки.
6. Представь удаление первого элемента данных. Почему хранить выбор по индексу стало бы опасно?

Главное для повторения: данные и виджеты — разные вещи; builder создаёт виджеты по мере
необходимости, grid delegate задаёт геометрию сетки, важное состояние живёт отдельно от ячеек.
